## 真实API验收细目

`integration/api_test.go` 仅在显式设置 `CAMPUS_API_TEST=1` 时运行。它创建三个带唯一标识的临时账号，结束后清理这些账号关联的数据；不会修改已有用户资料。付款链接只生成、不打开，不执行平台付款。

覆盖：正确/错误登录、匿名写入拒绝、发布人姓名、分类持久化、元分价格、清空描述、他人教材编辑拒绝、留言发布与空白拒绝、他人留言删除拒绝、本人删除、买卖订单查询、第三人订单访问拒绝、交易中下架拒绝、取消归属、重复旧取消不释放新占用、真实并发下单、未付款收货拒绝、签名沙箱链接生成，以及已删除账号的旧令牌拒绝。

## 支付测试依据

- 使用临时生成且相互独立的应用/平台RSA密钥测试签名；不使用真实私钥作为测试样例。
- SDK模拟HTTP测试保留真实请求编码和响应验签，覆盖篡改响应、错误业务码及关闭交易。
- 通知测试覆盖错误应用、错误收款方、错误事件类型、重复参数、金额非法、伪造签名、成功入账和重复通知。
- SQL Server方言的SQL mock覆盖写入失败回滚、重复流水核对、已取消订单拒绝入账、平台超时保留占用、旧链接有效期、取消时已支付同步入账、重复收货和权限。

## 尚未由本轮自动验证的事项

独立SQL Server数据库的“多通知同时入账/付款与取消同时发生”集成测试需要建库权限。当前账号没有建库权限，该测试被明确跳过。真实HTTP并发下单通过不等于所有支付竞态均已在真实数据库中验证。

正式商户上线、分账、退款、压力性能、定时关闭未付订单和生产高可用不属于本次课程版验收范围。退出登录清除前端令牌，但没有服务端令牌撤销表。数据库实体间的逻辑关联目前由应用检查，并未全部建立物理外键。
