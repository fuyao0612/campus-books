# Docker 部署与维护

前端与Go后端运行在Linux容器，本机SQL Server 2012继续保存业务数据。该Compose适合Windows课程演示环境，不包含数据库容器，也不会把密钥打进镜像。

## 首次部署

1. 启动Docker Desktop，选择Linux containers。
2. 复制 `.env.example` 为 `.env`，填写数据库、JWT和沙箱配置；将密钥放入 `secrets`。
3. 确认本机SQL Server启用TCP/IP，DSN中的固定端口可访问。
4. 在根目录执行：

```powershell
.\scripts\Prepare-Docker.ps1 -Start
```

脚本会定位Docker（兼容本机D盘安装）、补上凭据助手所在PATH、从现有本机DSN生成DOCKER_DB_DSN、检查Compose、构建并等待健康。已有DOCKER_DB_DSN不会被覆盖。

在其他机器或Linux上，可以手动填写容器可访问的数据库DSN，再使用 `docker compose up -d --build --wait`。Linux主机若无host.docker.internal映射，应填写实际可访问的数据库地址；不能照抄Windows路径和网络约定。

## 地址与密钥

| 调用方 | 地址 |
| --- | --- |
| Windows浏览器 | http://127.0.0.1:5174/login.html |
| 本机Postman/隧道 | http://127.0.0.1:8080 |
| 前端容器访问后端 | http://backend:8080 |
| 后端容器访问Windows数据库 | host.docker.internal:实际SQL端口 |

Compose只向后端传入所需配置，密钥目录只读挂载到 `/app/secrets`。`DB_DSN` 保留本机运行值，`DOCKER_DB_DSN` 用于容器。前端返回地址是浏览器使用的localhost地址，不能改为内部服务名web。

## 常用操作

```powershell
docker compose ps
docker compose logs --tail 80 backend web
docker compose up -d --build --wait
docker compose restart backend
docker compose stop
docker compose down
```

本机docker未在PATH时，使用 `& 'D:\Docker\resources\bin\docker.exe'` 替代命令中的 `docker`。镜像更新后需要 `up --build`，仅restart不会重新编译源码。

Compose down删除容器和内部网络，不删除Windows上的数据库或本机密钥。不要运行不理解的数据库清空或卷删除命令。升级前通过SSMS的“任务→备份”备份项目数据库，并保留 `.env`、`secrets` 的本机备份；不要把备份推送Git。

## 初始化账号

先在本机 `.env` 配置 `SEED_USER_NAME` 和 `SEED_USER_PASSWORD`，再运行：

```powershell
docker compose run --rm seeduser
```

seeduser是仅在手动调用时启用的工具服务，不随网站启动，不会自动创建公开默认账号。它读取.env中的账号初始化配置，并使用与后端一致的容器数据库地址。也可以在宿主机运行 `go run ./cmd/seeduser`。不要把密码写进可提交脚本或命令历史。已有账号时无需重复初始化；改密码配置后重复执行可能创建同名新用户，不能当作密码重置。

## 健康与停止

`/api/health` 表示HTTP进程在线；`/api/ready` 还会检查数据库。镜像使用自身的healthcheck子命令探测就绪，不依赖curl。前端等待后端健康后启动。

停止时向Go发送SIGTERM，服务器最多等待10秒完成已接收请求，之后再关闭连接池。健康检查不替代完整业务验收。

## 排错

- 端口占用：停止旧的go run和node服务，或通过BACKEND_PORT/FRONTEND_PORT选择其他本机端口；修改前端端口时也应调整支付宝返回地址。
- 数据库连接失败：核对TCP/IP、固定端口、数据库账号和DOCKER_DB_DSN主机名。容器中的localhost不是Windows。
- 密钥权限或文件不存在：检查本机secrets目录与文件名，挂载目标只读，不使用chmod 777作为通用解决方法。
- 凭据助手找不到：将Docker安装目录下resources/bin加入当前PATH，或使用准备脚本。
- 支付回调失效：保持cloudflared运行，域名变化后更新ALIPAY_NOTIFY_URL并重启后端。
